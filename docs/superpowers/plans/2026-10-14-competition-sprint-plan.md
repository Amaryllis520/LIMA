## 1. 总原则（沿整理文档 §6/§7）

1. 优先有效案例、可靠证据、完整材料；**不为扩范围牺牲 PoC 质量、误报控制
   与文档真实性**。V08（新漏洞类型）本轮明确不做。
2. 本地测试 / CI / 真实模型 / 真实沙箱四类证据分别记录，互不替代；
   无 finding 不证明零漏报；标签含引入提交不证明该版本仍受影响。
3. **10-20 代码冻结**，之后只收材料不改代码。
4. 单点止损：V02 若 10-19 晚未达成自动 runtime-confirmed 即停，维持已记录
   状态交卷。它不阻塞按期提交，但会缺少自动 PoC 闭环评分证据；avrcp 手动
   运行时证据只能支撑案例真实性，不能冒充自动链路闭合。
5. E08 干净部署冒烟是 10-20 代码冻结的强制门禁；E10/E11 在 10-15 前先建
   详细 Issue，再交给 wenxinliu52 的 Codex 执行。

### 第二阶段：主战役 V02（10-15 ~ 10-19，止损 10-19 晚）

**目标**：打通"漏洞假设 → 自动 PoC 转换 → runtime-confirmed"的真实闭环
（pilot 唯一开放项、赛题 PoC 质量评分项的自动链路证据）。

打法（薄版配方库，静态段接入，不做查询机制）：
1. 素材整理：expat 手动战役的触发组合（计数分配器扫 N + 外部实体 +
   `ParserCreate_MM` 自定义钩子）、dsoftbus/avrcp 靶场的时序锤击模式，
   按 CWE 族写成专家提示词配方段（现有通用手册之上的具体化层）。
2. 接入：`_SPECIALIST_PLAYBOOK` 按 CWE 键控的配方段 + 冻结测试。
3. 验证战役：官方验证 CLI 对 expat 对冲（每轮 35–60 分钟，可打 3–5 轮）；
   每轮战果入台账。
4. **止损线 10-19 晚**：未达成即停，台账如实记录。

并行小件（利用战役等待窗口）：
- V03 误报判据正式化（真模型评测 FP 1/8 + 非安全过滤 0/1 的判据落文档）。
- V05：avrcp 分支对齐复核结果进报告（与 V01 同源）。
- V06：补丁回归实战验收——用 #287 的 `run_patch_regression`（或手动
  双对照）对 avrcp 修复版复跑一次，作为修复建议评分项的实战证据。自动路径
  只有在平台已有匹配的 runtime-confirmed finding、同一 PoC 和补丁覆盖可用时才
  记为 #287 闭环；否则独立记录手工双对照的构建一致性、原版命中次数、修复版
  清洁次数、异常噪声和未验证的正常功能范围。
